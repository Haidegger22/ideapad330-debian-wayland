# 💻 Debian 13 + KDE Plasma (Wayland) на Lenovo IdeaPad 330 с внешнего NVMe

Полная инструкция: как поставить Linux на **внешний** NVMe-диск в USB-боксе, собрав систему
на ARM-плате (без x86-машины с Linux), не тронув Windows, и получить рабочий ноутбук
с Plasma на Wayland, русским интерфейсом и загрузкой с внешнего диска по умолчанию.

**Проверено на:** Lenovo IdeaPad 330-15ARR (81D2), Ryzen 5 2500U, Vega 8 + дискретная Radeon 540,
Wi-Fi RTL8821CE, внешний NVMe 256 ГБ в боксе ASMedia PH80-2364 (`174c:2362`, UASP, 5 Гбит/с).
Сборщик — Raspberry Pi 5 с Debian 13 (ARM64).

**Схема работы:**

```
   ┌───────────────────────┐        USB 3.0 (UASP, 5 Гбит/с)        ┌──────────────────────┐
   │  ARM-плата (Debian 13)│ ◄──────────────────────────────────►  │  Внешний NVMe 256 ГБ │
   │  debootstrap + qemu   │        система собирается здесь        │  ESP 512 МБ + ext4   │
   └───────────────────────┘                                       └──────────────────────┘
                                                                             │
                                          диск переносится в ноутбук ────────┘
                                                                             ▼
                                                    ┌──────────────────────────────────────┐
                                                    │ Ноутбук: UEFI → EFI/BOOT/BOOTX64.EFI │
                                                    │ Debian 13 + Plasma (Wayland) + Cinnamon│
                                                    │ Windows на внутреннем диске не тронут │
                                                    └──────────────────────────────────────┘
```

## Почему так, а не иначе?

Честная история с граблями — потому что половина времени ушла именно на них.

1. **Установщик на ARM не запустить**, а x86-машины с Linux под рукой не было. Поэтому система
   не «устанавливалась», а **собиралась**: `debootstrap --arch=amd64 --foreign` плюс
   `qemu-user-static`, который позволяет выполнять x86-код на плате ARM. Заняло 18 минут.
2. **Рабочий стол в эмуляции не ставится** — KDE через qemu это часы работы и риск.
   Поэтому: сначала голая консоль, потом ноутбук грузится, и Plasma доставляется **нативно по SSH**.
3. **Windows не трогаем вообще.** Загрузчик ставится съёмным путём (`--removable --no-nvram`)
   на EFI-раздел внешнего диска. Windows и его загрузчик остаются как были: вынули диск — грузится Windows.
4. **Локальный прокси рвёт загрузки Debian.** `debootstrap` падал с `Couldn't download packages`
   на случайных 3–6 пакетах. Лечится `unset http_proxy ...` + повторами + `Acquire::Retries`.
5. **Минимальный набор без `systemd-sysv` — это неработающая система.** `--variant=minbase`
   содержит только пакеты уровня «required», а `systemd-sysv` (это и есть `/sbin/init`) — уровня
   «important». Итог: первая загрузка падает в аварийную оболочку с
   `Target filesystem doesn't have requested /sbin/init`, где нет ни apt, ни сети.
6. **Русский язык не включался, потому что локаль не была сгенерирована.** В системе были только
   `C`, `C.utf8`, `POSIX`. Настройки языка при этом можно ставить какие угодно — приложения
   всё равно откатывались на английский, а Qt писал `Detected locale "C"`.
7. **`--no-install-recommends` для рабочего стола — источник «глюков».** Dolphin открывался и висел:
   не было `kio-extras`, `baloo6`, генераторов миниатюр. Экран входа падал с чёрным экраном:
   не было темы `sddm-theme-debian-breeze`. Экономия ложная — ставить рабочий стол нужно с рекомендациями.
8. **X11 на двух видеокартах забирает не ту карту.** Внутренний экран подключён к встроенной Vega,
   но X-сервер занимал дискретную Radeon 540 — чёрный экран, в логе `flip queue failed`.
9. **Через USB-мост не работает TRIM.** Проверено на двух разных машинах с тем же боксом —
   это свойство адаптера, настройками не лечится. Скорость: запись ~327 МБ/с, чтение ~373 МБ/с.
10. **F-ряд зависит от прошивки, а не от Linux.** Быстрее всего решается в BIOS (Hotkey Mode),
    и настройка действует сразу в обеих системах.

## Что понадобится

- **Ноутбук** с UEFI (Secure Boot можно не отключать) и USB 3.0.
- **Внешний NVMe/SATA-диск в USB-боксе** — 256 ГБ и больше. Внутренние диски ноутбука не понадобятся.
- **ARM-плата с Linux** (Raspberry Pi 4/5, Orange Pi и т. п.) — она будет «станочной» системой сборки.
  Нужны: `debootstrap`, `qemu-user-static`, `binfmt-support`, свободные 5 ГБ.
- **Проводная сеть или Wi-Fi на ноутбуке** для этапа доставки рабочего стола.
- Понимание, что диск будет полностью перезаписан: **всё содержимое внешнего диска будет стёрто.**

## Часть 1. Сборка системы на ARM-плате

Подключите внешний диск к плате. Проверьте, что это именно он (не перепутайте с системным!):

```bash
lsblk -o NAME,SIZE,MODEL,TRAN          # TRAN должен быть usb
wipefs -n /dev/sdX                     # покажет, есть ли что-то на диске
sudo smartctl -i -d sntasmedia /dev/sdX  # модель, серийник; для ASMedia нужен -d sntasmedia
```

Скрипт `scripts/01-install-debian-to-disk.sh` делает всё сразу: предохранители, разметку GPT
(EFI 512 МБ + ext4 на остальное), `debootstrap`, ядро, прошивки, загрузчик, пользователя и автологин.

```bash
TARGET_USER=user TARGET_HOST=debian-laptop DISK=/dev/sdX ./scripts/01-install-debian-to-disk.sh
# проверка: в конце скрипт печатает ядро, initrd, содержимое EFI и число ссылок в grub.cfg
```

**Что важно в нём:**

- предохранители: цель обязана быть на `TRAN=usb`, иначе скрипт откажется работать;
- прокси снимается принудительно, иначе часть пакетов не скачается;
- загрузчик ставится как `--removable --no-nvram` со `shim-signed` — UEFI найдёт его без записи в NVRAM;
- проверка `fsck` в initramfs: без пакета `e2fsprogs` система грузится без проверки корня
  (лечится `scripts/05-fix-initramfs-fsck.sh`).

## Часть 2. Первая загрузка в ноутбуке

1. Выключите ноутбук, вставьте диск, включите и нажмите **F12** — выберите загрузку с внешнего диска.
2. Система поднимется **в консоли** под вашим пользователем (автологин включён специально).
3. **Задайте пароль сами** — это единственное, что нельзя сделать удалённо:

```bash
sudo passwd $USER     # именно через sudo: обычный passwd спросит СТАРЫЙ пароль, которого нет
```

4. Узнайте адрес и подключите сеть:

```bash
ip -4 addr            # адрес
nmtui                 # текстовый интерфейс подключения к Wi-Fi
```

Если что-то пошло не так и вы оказались в аварийной оболочке (`(initramfs)`), а на экране
`Target filesystem doesn't have requested /sbin/init` — значит в систему не попал `systemd-sysv`.
Загрузитесь снова с флешки/платы и запустите `scripts/06-fix-init-system.sh`.

## Часть 3. Что доставить в базовую систему

Дальше всё делается **по SSH с платы**, ключ уже прописан в системе:

```bash
ssh user@<адрес-ноутбука>
```

Если система собрана минимальным набором, проверьте обязательное:

```bash
ls -l /sbin/init            # должен вести на ../lib/systemd/systemd
locale -a | grep ru_RU      # должна быть строка ru_RU.utf8
systemctl is-enabled ssh NetworkManager
```

Чего не хватает — доставляется скриптами:

- `scripts/06-fix-init-system.sh` — `systemd-sysv`, `libpam-systemd`, идентификатор машины, службы;
- `scripts/08-fix-locale-ru.sh` — генерация русской локали (без неё интерфейс останется английским);
- `scripts/04-check-missing-recommends.sh` — покажет, каких рекомендованных пакетов не хватает;
- `scripts/07-copy-wifi-and-network-rights.sh` — переносит профили Wi-Fi (пароли не печатаются)
  и выдаёт права на управление сетью (иначе в консоли: `Not authorized to control networking`).

## Часть 4. Рабочий стол: Plasma на Wayland

```bash
./scripts/02-install-plasma-wayland.sh        # kde-plasma-desktop + sddm с сессией Wayland
./scripts/03-russian-plasma-and-panel.sh      # русский язык, раскладка, панель наверх
```

**Ставьте рабочий стол БЕЗ `--no-install-recommends`** — иначе файловый менеджер открывается и висит,
а экран входа падает с чёрным экраном. Обязательный минимум, который легко потерять:
`kio-extras`, `baloo6`, `ffmpegthumbs`, `kdegraphics-thumbnailers`, `kimageformat-plugins`,
`sddm-theme-debian-breeze`, `kscreen`, `power-profiles-daemon`.

Проверка, что сессия действительно Wayland:

```bash
loginctl list-sessions --no-legend
loginctl show-session <номер> -p Type --value     # wayland
pgrep -a kwin_wayland plasmashell
```

Хотите вторую оболочку «как в Mint» — Cinnamon ставится рядом и не мешает Plasma:

```bash
sudo apt install cinnamon-desktop-environment cinnamon-l10n mint-y-icons
```

На экране входа появятся отдельные пункты. Имена сессий лучше сразу сделать однозначными
(`Cinnamon (обычная, X11)` / `Cinnamon (Wayland, экспериментальная)`), иначе легко перепутать:
в Debian они отличаются только припиской «(Experimental)».

## Часть 5. X11 на двух видеокартах (чёрный экран)

Если X11-сессия даёт чёрный экран, а система жива — почти наверняка X-сервер занял дискретную
видеокарту, к которой не подключён экран. Проверка и лечение:

```bash
./scripts/09-pin-x11-to-igpu.sh     # сам найдёт карту с внутренним экраном и пропишет привязку
```

Скрипт смотрит, на какой карте `eDP-1` в состоянии `connected`, и создаёт
`/etc/X11/xorg.conf.d/20-igpu.conf` с `BusID` этой карты. После — `systemctl restart sddm`.
На Wayland эта проблема не возникает: композитор сам выбирает нужную карту.

## Часть 6. Загрузка с внешнего диска по умолчанию

Чтобы не нажимать F12 каждый раз, нужна запись в NVRAM прошивки:

```bash
./scripts/10-set-usb-boot-first.sh        # создаст запись и поставит её первой
efibootmgr | head -3                      # проверка: BootOrder начинается с нашей записи
```

Записи Windows остаются следом — при отключённом диске ноутбук грузится в Windows как обычно.
Учтите: **Windows иногда переписывает порядок загрузки** после крупных обновлений — тогда
скрипт достаточно запустить заново.

## Часть 7. Клавиши F1…F12 (Hotkey Mode)

На ноутбуках Lenovo обычное нажатие F1…F12 по умолчанию даёт мультимедиа-функции
(громкость, яркость, режим самолёта). Меняется это **в прошивке** — и тогда действует в обеих ОС:

1. Перезагрузка → при логотипе Lenovo нажать **Fn + F2** (именно с Fn: одиночная F2 может
   сработать как «громкость меньше»). Есть кнопка **Novo** — можно войти через неё.
2. Раздел **Configuration** → пункт **Hotkey Mode** (он же **Fn Lock**, **Action Keys Mode**) → **Disabled**.
3. Сохранить: **Fn + F10** (или меню Exit → Save Changes and Exit).

После этого обычное нажатие — F1…F12, а мультимедиа — через Fn.

**Если в BIOS такого пункта нет** — есть программный путь, но с оговоркой: F-ряд **неоднороден**.
Часть клавиш прошивка отдаёт как мультимедиа (`mute`, `volumedown`, `brightnessdown`), а часть —
уже как функциональные (`f4`, `f5`, `f6`, `f8`). Если поменять местами всё подряд, работавшие
клавиши сломаются. Готовый пример с пояснениями и методом замера — `scripts/11-fn-swap-keyd.conf.example`.

## Часть 8. Что ожидать по скорости и износу

```bash
dd if=/dev/zero of=$HOME/test.bin bs=1M count=1024 oflag=direct conv=fdatasync   # запись
dd if=$HOME/test.bin of=/dev/null bs=1M iflag=direct                             # чтение
sudo smartctl -A -d sntasmedia /dev/sdX | grep -iE "Temperature|Percentage Used|Available Spare"
```

Ориентиры для USB 3.0 (5 Гбит/с) + UASP: **чтение 350–380 МБ/с, запись 300–330 МБ/с**. Это уровень
хорошего внутреннего SATA-накопителя: разница на глаз почти не заметна. Диск, воткнутый напрямую
в M.2, был бы в 4–5 раз быстрее, но в этой модели слот занят Wi-Fi.

**TRIM через такой мост не работает** (`lsblk -D` покажет нули). Это свойство адаптера:
лечится только другим адаптером с поддержкой очистки. На практике означает, что со временем,
по мере заполнения диска, скорость записи может слегка проседать.

## Часть 9. Виджеты температур на панели (процессор и внешний NVMe)

На панели две цифры в реальном времени: **CPU** и **NVMe**. Цвет по порогам:
**зелёный до 49°**, **жёлтый 50–69°**, **красный от 70°**.

Почему не штатными плазмоидами:

- в Debian плазмоида «вывод команды» нет — в `plasma-widgets-addons` лежат только
  `systemmonitor.*` (проверено: `ls /usr/share/plasma/plasmoids/ | grep -i command` пусто);
- штатный «Системный монитор» видит температуру процессора, но **не видит NVMe за USB-мостом**:
  диском управляет `uas`, а не драйвер `nvme`, поэтому hwmon-датчика у диска просто нет.

Значит, данные нужно добывать самим, а показывать — своим плазмоидом.

### Откуда берутся цифры

| Что | Источник | Особенность |
|---|---|---|
| Процессор | `/sys/class/hwmon/hwmon*/name` = `k10temp` → `temp1_input` (миллиградусы) | читается без root |
| NVMe за USB-мостом | `smartctl -A -d sntasmedia /dev/sdX` | **нужен root**, hwmon нет |

Требование root решается без расширения прав: отдельная маленькая служба с таймером раз в 30 секунд
читает температуру и служебные данные (SMART), а результат кладёт в файлы, доступные пользователю:
`/run/nvme-temp` (число) и `/run/nvme-smart` (сводка SMART). Виджет читает уже их.

### Установка

```bash
./widgets/00-install-widgets.sh      # пакеты, служба, апплет, добавление в панель
```

Скрипт идемпотентный: если апплет уже в панели, он его не добавит второй раз
(`addWidget` копий не проверяет — это грабли, на которые легко наступить, см. ниже).

### Файлы

| Файл | Что делает | Куда устанавливается |
|---|---|---|
| `00-install-widgets.sh` | установка целиком | — |
| `01-nvme-temp-report.sh` | читает SMART и пишет `/run/nvme-temp`, `/run/nvme-smart` | `/usr/local/sbin/nvme-temp.sh` |
| `nvme-temp.service` / `nvme-temp.timer` | запуск раз в 30 секунд | `/etc/systemd/system/` |
| `02-temp-line.sh` | формирует строку «CPU 40° · NVMe 59°» | `~/.local/bin/temp-line.sh` |
| `plasmoid-tempwidget/` | сам апплет (`metadata.json` + `contents/ui/main.qml`) | `~/.local/share/plasma/plasmoids/ru.artem.tempwidget/` |
| `04-temp-widget-float.py` | альтернатива: плавающее окно GTK3 + Cairo | `~/.local/bin/` |

Апплет — это QML-файл на 60 строк: строка из скрипта разбирается регуляркой, значения красятся по
порогам, обновление раз в 5 секунд. Команда вызывается из QML через `org.kde.plasma.plasma5support`
(движок `executable`), поэтому нужен пакет `qml6-module-org-kde-plasma-plasma5support`.

### Проверка

```bash
cat /run/nvme-temp                      # температура диска, которую прочитала служба
~/.local/bin/temp-line.sh               # строка целиком
systemctl status nvme-temp.timer        # служба жива
```

Снимок экрана для проверки глазами (из SSH, иначе spectacle не выберет платформу):

```bash
export XDG_RUNTIME_DIR=/run/user/$(id -u) DBUS_SESSION_BUS_ADDRESS=unix:path=/run/user/$(id -u)/bus
QT_QPA_PLATFORM=wayland WAYLAND_DISPLAY=wayland-0 spectacle -b -n -f -o /tmp/shot.png
```

### Грабли (проверено на практике)

1. **`addWidget` не идемпотентен.** Три вызова — три копии в панели, и это сразу видно пользователю.
   После добавления всегда считать копии: `grep -c "plugin=<id>" ~/.config/plasma-org.kde.plasma.desktop-appletsrc`
   и `print(JSON.stringify(panels()[0].widgetIds))`. Лишние убирать: `panels()[0].widgetById(<id>).remove()`.
2. `panel.widgets` — **функция**, а не список: `.length` вернёт `0` и введёт в заблуждение.
   Список идентификаторов — `panel.widgetIds`.
3. Массивы, которые возвращает движок сценариев, **без `.map`/`.join`** — перебирать обычным `for`.
   Скрипт для `evaluateScript` писать **одной строкой**: многострочный падает с `@:N %entry@:N`.
4. Изменённый QML панель подхватывает только после перезапуска:
   `systemctl --user restart plasma-plasmashell.service`.
5. Если делать виджет плавающим окном (вариант `04-…`), то **в Wayland окно не может задать себе
   позицию** — место определяет правило KWin в `~/.config/kwinrulesrc` (`wmclass` = имя из
   `GLib.set_prgname`, `position=…` + `positionrule=2`, `aboverule=2`, `noborderrule=2`),
   после чего `qdbus6 org.kde.KWin /KWin reconfigure`. И задавать размер нужно дважды —
   `set_size_request()` И `set_default_size()`, иначе GTK растянет окно по вертикали.

### Заодно: здоровье накопителя

Служба пишет сводку SMART в `/run/nvme-smart`. Полезно смотреть:

- **`Critical Warning: 0x00`** — нет ни одного флага тревоги;
- **`Warning Comp. Temperature Time: 0`** — диск ни разу не переходил свой порог предупреждения
  (если счётчик нулевой, значит рабочие температуры ниже внутренней границы диска);
- **`Percentage Used`** — износ; **`Available Spare`** — резерв блоков;
- **`Unsafe Shutdowns`** — растёт, когда питание снимают без размонтирования.

Про извлечение: внешний диск на USB нельзя выдёргивать на ходу. Перед тем как вынуть —
`sync`, а лучше размонтировать: счётчик аварийных отключений растёт именно от этого.

Замер на нашем экземпляре: процессор в простое 35–45°, накопитель 59–66° (62° в покое). Для NVMe
это тёплый край: внутренний диск в ноутбуке держал бы 35–50°. Причина не в охлаждении (стоит медный
радиатор на открытой плате), а в способе подключения: через USB-мост накопитель не уходит
в энергосберегающие режимы так же охотно, как на прямой шине, и греется даже без нагрузки.
Сам диск при этом здоров: `Critical Warning 0x00`, порог предупреждения ни разу не превышен,
износ 0 %, резерв 100 %.

## Частые проблемы

| Симптом | Причина | Решение |
|---|---|---|
| Первая загрузка падает в аварийную оболочку, `run-init: /sbin/init: No such file` | в минимальном наборе нет `systemd-sysv` | `scripts/06-fix-init-system.sh` |
| Тот же шелл, `passwd: Authentication token manipulation error` | у учётки нет пароля, `passwd` требует старый | `sudo passwd <пользователь>` |
| Wi-Fi не подключается, в журнале `Not authorized to control networking` | нет прав NetworkManager в консольной сессии | `scripts/07-copy-wifi-and-network-rights.sh` |
| Интерфейс английский, хотя язык выставлен | локаль не сгенерирована (`locale -a` без `ru_RU`) | `scripts/08-fix-locale-ru.sh` |
| Dolphin открывается и висит, в журнале `Failed with result` | нет `kio-extras`/`baloo6` (ставили с `--no-install-recommends`) | доставить рекомендованные пакеты |
| Экран входа чёрный, система при этом жива | нет темы `sddm-theme-debian-breeze` | поставить тему, `systemctl restart sddm` |
| X11-сессия чёрная, в логе `flip queue failed` | X занял дискретную видеокарту | `scripts/09-pin-x11-to-igpu.sh` |
| Снова грузится Windows при подключённом диске | Windows переписал `BootOrder` | `scripts/10-set-usb-boot-first.sh` |
| `sudo` в чужой системе недоступен из-за узкого списка прав | правки файлов требуют root | собрать маленький deb с `postinst` и поставить через `dpkg -i` |
| В панели несколько одинаковых виджетов температуры | `addWidget` вызвали повторно | лишние: `panels()[0].widgetById(<id>).remove()` |
| Виджет температуры всегда жёлтый | пороги не подходят под рабочие температуры | правьте пороги в `main.qml` (`colourFor(…, 50, 70)`) |
| Диагноз «на словах» расходится с реальностью | нет данных из журнала | `e2fsck -n`, затем смонтировать и прочитать журнал: `journalctl -D /mnt/target/var/log/journal -b` |

## Диагностика: читать журнал прямо с диска

Самый надёжный способ понять, что произошло на ноутбуке, — вернуть диск к плате и прочитать его
журнал (там сохраняются все загрузки):

```bash
sudo mount -o ro /dev/sdX2 /mnt/target
sudo journalctl -D /mnt/target/var/log/journal --no-pager -b -p err
sudo journalctl -D /mnt/target/var/log/journal --no-pager -b | grep -iE "remount|network|passwd|sddm"
sudo umount /mnt/target
```

Так были найдены причины сразу трёх «загадок»: `Not authorized to control networking`
(права NetworkManager), `unix_chkpwd: password check failed` (пароля нет), и падение экрана входа.

## Альтернативы

- **Обычный установщик с флешки.** Если есть флешка — официальный образ Debian 13 и обычная
  установка на внешний диск руками. Наш путь с `debootstrap` нужен, когда хочется собрать систему
  заранее на плате и не возиться с мастером установки.
- **Linux Mint / Cinnamon на X11.** Проще «из коробки», но Wayland там экспериментальный
  (в Cinnamon сессия так и называется: *Cinnamon on Wayland (Experimental)*).
- **GNOME на Wayland.** Больше памяти в простое (1,5–2 ГБ против 0,9–1,2 ГБ у Plasma) и выше
  расход батареи — на ноутбуке с 8 ГБ разница заметна.
